## Public interfaces
- Confirmation policy (`safety.py`, #35): `confirmation_policy() -> {"mode": "ask"|"decline"|"auto", "seconds_left", "default_seconds", "max_seconds"}`; `set_confirmation_mode(mode, seconds=None, *, by="")` (`auto` in memory only, default 1 h, capped 4 h, raises `ValueError` on bad input; `ask`/`decline` persist as `safety.confirmation_mode`); `disable_auto_approve(*, by="")`. `auto` covers DESTRUCTIVE from `safety.AUTO_SOURCES` (web, web-panel, voice, voice-live, cli, cli-ask) only, with a real confirmer; CRITICAL, hard refusals and the denial memory are unchanged. `allow_destructive: false` = `decline`. Audit: `safety.auto_approved`, `safety.mode_changed`, `safety.auto_expired`. `check_path` refuses writes to `settings.json`. Skills must never call the setters (pinned by `tests/engine/test_confirmation_policy.py`).
- Live voice audio I/O (`live.py`, #83): `LiveSession(observer=, confirmer=, model=, source=None, sink=None)`; default = `SoundDeviceSource`/`SoundDeviceSink` (laptop mic/speaker, unchanged). Network client: `net = NetworkAudio(); s = LiveSession(source=net, sink=net, observer=..., confirmer=...)`, run `s.run()` on a worker thread (blocking, returns tool-call count).
  - In: `net.push_input(bytes)` from any thread — PCM16 mono little-endian **16 kHz** (`SEND_SAMPLE_RATE`), any chunk size (odd trailing byte is carried; bounded 100 chunks, oldest dropped; audio pushed before connect is kept).
  - Out: `net.pull_output(timeout) -> bytes | Control.CLEAR | Control.CLOSED | None` — PCM16 mono **24 kHz** (`RECEIVE_SAMPLE_RATE`). `CLEAR` = barge-in: the client must drop audio it already buffered (uncollected audio is dropped server-side). `CLOSED` = session over. `None` = timeout. Output backlog bounded (400 chunks, oldest dropped).
  - Stop: client disconnect → `net.close()` (ends the session cleanly); `s.stop()` also closes `net`, so a reader blocked in `pull_output` always gets `CLOSED`. Run the reader as a loop until `CLOSED`; no other thread is left behind.
  - Custom backends implement `AudioSource.capture(put, astop, on_ready)` / `AudioSink.play(audio_queue, stop)` + `interrupt()`. Pinned by `tests/engine/test_live_audio.py` (fake genai client).

- Live turn hygiene (`live.py`, #97): transcripts and replies go through `clean_transcript` (strips `<ctrlNN>`/`<unusedNN>`/turn tokens, removes Devanagari/Arabic script — never displayed, never transliterated: letter-by-letter Latin turned "turn off this flashlight" into "tarn of dis flaishalaait"). A turn with no audio, no usable text and no tool call, after the model began or the user spoke, emits `answer` = `EMPTY_REPLY_TEXT` and audits `live.empty_reply` (text only, not spoken). `voice.language`: `""` or `en+ur-roman` = English + Roman Urdu (recognition `en-US`, base language English: replies in English); any other value is a BCP-47 code as before. Config default stays `""` because `platform/stt.py` passes `voice.language` to whisper. Pinned by `tests/engine/test_live_turns.py`.
- English user transcript (`live.py` + `platform/stt.py`, #100): Gemini input transcription cannot be pinned to English (language_codes is ignored; Hindustani/accented English returns Devanagari), so each turn's mic audio (`_mic`, last 30 s) is run through faster-whisper `task="translate"` (`stt.translate_to_english`, multilingual `voice.translate_model`, default `base`, preloaded in a daemon thread at session start; `voice.live_translate` false disables). `heard` carries the English text; the reply never waits (Whisper runs in a task), only the `listening` marker is held back (<= `TRANSLATE_TIMEOUT` 45 s) so the client's user bubble is not split. Until the model is loaded (`stt.translate_ready()`), or on failure, the fallback is Gemini's text with foreign script stripped; `heard_partial` shows `…` while Devanagari-only. Tests set `stt.translate_available` false in the `backend` fixture so no model is loaded.

## Gotchas
- Settings writes (#163): `config._deep_merge` deep-copies (loaded settings never alias `DEFAULT_SETTINGS`); every read-modify-write goes through `config.update_settings(mutate)` (loads a private copy and saves under `_settings_lock`) — `/api/settings` and `safety._persist_mode` use it, so they cannot lose each other's update. Do not `load_settings()` → edit → `save_settings()` in new code (`skills/llm_admin.py` still does; skills-owned). TTS: edge-tts 7.2.x gets HTTP 403 from Microsoft (needs `edge-tts>=7.3.1`, verified live; requirements-linux.txt is qa-owned). `voice.tts_problem()` turns `tts.speak` failure strings into an audit `voice.tts_problem` + an `error` observer event and a `kravein voice test` message, instead of silent mute. Pinned by `tests/engine/test_settings_writes.py`.
- Polling cap (#175): `task_status` keeps `(turn_no, state signature)` on its context; a repeat in the same turn with no state change (`TaskManager.state_sig`: id/status/step/tool, never elapsed time) returns "No change since your last check…". Each call is still a tool round, so it counts toward escalation. `voice.self_test` runs mic / recognition / speech output independently (TTS is reached with no mic), live capture only when mic+STT are ok, and ends with a per-stage summary. Pinned in `test_tasks.py`, `test_voice.py`.
- History store (`agents/history.py`) serialises `ToolCall.signature` bytes (Gemini `thought_signature`) as `{"__b64__": ...}` and decodes on load; never `default=str` (it stored a repr, Gemini answered 400 on turn 2, #154). Legacy repr rows load as `None` + audit `agent.history_signature_dropped`. `_to_gemini_contents` flattens a step whose first call has no real signature (and its results) to text: Google's documented dummy signature (`context_engineering_is_the_way to_go`) is REJECTED by gemini-3.5-flash-lite through the SDK ("Corrupted thought signature"; verified live 2026-11-02), so do not reintroduce it. Pinned in `test_agent_history.py`, `test_llm.py`.
- Agent profiles (#132): `kravein/agents/<name>/SKILL.md` (frontmatter `name`, `purpose`, `tools` = categories and/or skill names, optional `model`, `report_max_chars`; body = instructions appended to the shared prompt). Strict hand-written parser (no PyYAML: transitive only); any malformed profile raises `ProfileError`. `Agent(profile=, thread_id=)`: the profile's tools are the only ones sent AND `registry.dispatch(allowed=)` refuses/audits (`skill.profile_refused`) any other call, resolved through aliases; no profile = all tools, unchanged. `model` (`provider:model`) is applied via `LLM.complete(prefer=)` (#138); `report_max_chars` caps a `delegate` report. History (`agents.db` in STATE_DIR, replace-in-transaction per save, saved in `ask()`'s `finally`): `llm.history_token_budget` 24000 (chars/4); over budget the oldest whole turns (cut only at a user message, current turn never) fold into a rolling summary (one tool-less `complete`; failure/empty -> plain trim, `agent.summary_failed`); trims to 60%. `llm.tool_result_max_chars` 12000 caps a result in history with a marker; the full text stays in the audit (`skill.ok` result cap 50000, `audit.RESULT_MAX_CHARS`). `max_history` is now an optional extra count cap (default 0). `@skill(aliases={"old": {"action": "x"}})`: preset keys always win over caller args (audit `skill.alias`); aliases never reach the schema. Web sessions pass `thread_id=principal_thread_id("web", principal)` (sha256 of channel+principal, never the raw device id/token); two tabs of the same principal share one thread and the last save wins (documented limit). `agents.db` is 0600; a thread saved mid-tool-call gets its dangling calls closed on load. `tests/engine/conftest.py` starts every engine test from `DEFAULT_SETTINGS` (the owner's real settings.json no longer leaks in) and re-exports the shared `tests/conftest.py` helpers. Pinned by `tests/engine/test_agent_profiles.py`, `test_agent_history.py`, `test_agent_threads.py`.
- Orchestrator + `delegate` (#138): `agents.orchestrator` (default **false**) makes web, local voice and CLI (`agent.make_agent`) use the `orchestrator` profile; off = exactly `Agent(source=...)`. Jobs, daemon and WhatsApp never use it. A broken profile falls back to the all-tools agent (`agent.orchestrator_unavailable`). `delegate(agent, task, context)` (category `agents`, hidden from profile-less agents, not a routing category) runs the sub-agent **on the caller's thread** inside the caller's `confirmer_scope`: its confirmer only prefixes the card with `<agent>: ` and returns the owner's answer unchanged (timeout/dropped socket/no confirmer = deny; no confirmer at all stays no confirmer), `source` is the parent's (auto-approve and unattended decisions key on it), and it shares the parent's `TurnMemory`. A decline or an unattended refusal ends the child's turn (`Agent.end_turn_check`); the outcome (`declined`/`needs-approval`/`partial` on stop or timeout/`failed`) is set by code, never by what the model says. No nesting: `Agent` raises `ProfileError` for `delegate` in any profile but the Orchestrator at depth 0, and `delegate` refuses other callers. Report = `OUTCOME/SUMMARY/CHANGED/EVIDENCE/QUESTIONS`, parsed from the last block, else built from the turn (never empty), capped by the profile's `report_max_chars` (default `agents.report_max_chars` 1500); the child's raw tool output stays in its own thread (`d:<parent thread>`). Caps: `agents.delegate_max_rounds` 6, `agents.delegate_timeout_seconds` 300 (a `_LinkedStop`, polled between rounds like the stop event: it cannot interrupt a provider call or a confirmation wait, so the cap can overrun). Escalation: after `agents.escalate_after_rounds` (3; 0 off) tool rounds, an Orchestrator with at least one other profile sees only `delegate` (schema and dispatch narrowed) plus a system note (`agent.escalated`). `audit.context(...)` stamps every record of the child's turn with `delegation`, `agent`, `parent_source`; `agent.delegate_start/_end` bracket it. Observer frames from the child carry `data.agent` and `data.delegation` (web does not render them yet). A profile `model` is `provider:model`, passed as `LLM.complete(prefer=)`: that provider is tried first, failover and breaker unchanged. Pinned by `tests/engine/test_delegate.py`.
- `config.py` (#124): XDG only (`~/.config|.local/share|.local/state|.cache/kravein`). The Windows tree, the in-repo `config/*.json` fallback and the pre-rename XDG fallback are deleted; a machine on the kravein paths is unaffected. Guarded by `tests/engine/test_config_paths.py`.
- Declined-retry stop (#114): `safety.TurnMemory` (denied targets + `retried_declined`) is what `confirmer_scope` installs; a call refused because its target was already declined sets the flag (`safety.retried_declined_target()`), and `Agent.ask` then skips the rest of the batch and ends the turn with "Okay, I won't do that." (audit `safety.declined_turn_stop`). Different targets are still asked — no blanket lockout. Live voice runs one scope per tool call, so `LiveSession` holds one `TurnMemory` per model turn (reset in `_reset_turn`). Same-path keys for `delete_path permanent=True` and `run_command rm <path>` come from `_target_keys` on the action text; pinned by `tests/engine/test_declined_turn.py`.
- `service.py` (#76): the unit is never enabled (owner: manual on/off). Host comes from `web.env` `KRAVEIN_LAN_HOST`, port 8787. `phones remove` refuses ambiguous names; `open` never prints the token. Pinned by `tests/engine/test_service_cli.py` (systemctl/HTTP stubbed).
- Zen provider (#129): `llm.ZenProvider` subclasses `NovaRouterProvider` (same OpenAI wire shape; `label`/`_key`/`_timeout` hooks), first in `LLM._all()`. Defaults `llm.zen_base_url=https://opencode.ai/inference/openai/v1`, `llm.zen_model=deepseek-v4.1-flash` (verified in the Zen docs and `GET https://opencode.ai/inference/v1/models`), `zen_timeout_seconds` 45, no tool cap. Key: `config.zen_api_key()` = `opencode_zen_api_key` in api_keys.json or `OPENCODE_ZEN_API_KEY`; redacted in audit. `kravein doctor` prints `ZenProvider.report()`. `config._migrate_user_settings`: a settings.json holding exactly the old defaults (`cline`, `[cline, novarouter]`) is read as unset so Zen leads. A Zen 402 (no credit) or 429 (usage limit) raises `ProviderBlocked` and the facade opens the breaker at once for `llm.zen_blocked_cooldown_seconds` (1800); `reset_llm_failover` clears it. An unparseable `api_keys.json` prints a one-time `[config]` warning (position only). Pinned by `tests/engine/test_zen.py`. `tests/conftest.py` has an autouse fixture blanking `config.zen_api_key` because `_agent_with` does not stub zen.
- Tests stub all three providers; breaker tests monkeypatch `config.STATE_DIR`. See `CLAUDE.md` "Testing conventions".
- Tool routing is pinned by `tests/engine/test_tool_routing.py` (default off, only `auto` enables, fail-open, `more_tools` edge cases, byte-stable tool list between rounds).
- Dynamic LAN address (`discovery.py`, #105): `web.env` `KRAVEIN_LAN_HOST=auto` (installer default); an explicit address no longer held counts as `auto`. `pick_address`: held explicit → itself; one real candidate → it; several → the default-route interface (`/proc/net/route`); several with no default route → `None` (refuse, never first). Real = psutil private IPv4, not loopback/link-local/virtual (`docker*`, `br-*`, `veth*`, `tun*`… same list as the old installer filter). `serve --lan --follow` (unit passes it; `--host auto` implies it) → `server._serve_following` re-binds uvicorn in-process when `AddressWatcher` (5 s poll) sees a change: same cert/token, Host allowlist swapped, mDNS re-advertised; no address → waits. `Advertiser` announces `_kravein._tcp` port 8787, TXT `fp` (cert sha256[:16]) + `v=1`, bound to the one interface; without `zeroconf` it logs `discovery.unavailable` and the server still runs. `service.current_host()` resolves auto/stale for `kravein start|status|…`. Mobile data cannot reach a LAN address (status says so). Pinned by `tests/engine/test_discovery.py`; `test_service_cli.py`'s fixture stubs `discovery.interface_addresses` so the dev machine's real network does not leak in.
- `serve --lan` address choice (without `--follow`) is `cli._pick_lan_host`: explicit `--host` must be a held private address; several candidates and no `--host` → refuse and list (never `addresses[0]`). Pinned by `tests/engine/test_serve_lan_host.py`.
- `classify_command` hard-blocks shell writes to Kravein's `settings.json` (redirects, sed -i, cp/mv/tee/dd/ln, editors, interpreters); reads stay allowed. Text matching only: a path assembled at run time is not caught, and a bare `settings.json` counts as ours (cwd unknown). Pinned in `tests/engine/test_confirmation_policy.py` (#40). Globs matching the file and any write-class command naming its directory (`cp -r x dir/`, `cd dir && sed -i *`) are blocked too; bare globs without a directory part and the parent `~/.config` are not.
- Proposals (#143, `agents/proposals.py`): table `proposals` in `agents.db`; fields `{id, title, reasons[], kind delegate|note, agent?, task?, risk low|major, status, created_by, created_at, decided_at?, decided_by?, result?}` (times = epoch seconds; `decided_by` = `web`/`phone`/source label, never a token). State machine, each step one `UPDATE ... WHERE status IN (...)`: pending -> approved|declined|expired; approved -> running -> done|failed; approved -> expired if never started (TTL `agents.proposal_ttl_days` 7, swept on every read + hourly in the server). Caps: `agents.proposal_max_pending` 20, identical pending titles refused. `decide()` is the single gate: only `OWNER_SOURCES` (web, web-panel, phone, voice, voice-live, cli, cli-ask) — jobs/daemon/WhatsApp/`schedule:*` get `NotAllowed` (audit `proposal.decide_refused`); deciding twice returns the proposal unchanged. **Approving confirms nothing**: REST `POST /api/proposals/{id}/decide` (`{decision, session_id?}`) starts the task as an Orchestrator turn (`Owner approved proposal #id: ...`) in an attached, idle session of the *same principal* (`session_id` narrows it; busy/none = stays `approved`), via `server._run_approved` with that session's agent + confirmer; sessions also pick up approved ones when they open (`_pickup_approved`). `decide_proposal` skill (Orchestrator only, live owner source) runs `delegate` inline under the current confirmer. `kind=note` approve = done at once. Frames: `events.broadcast("proposal", proposal=...)` — wire key is `t` like every web frame, not `type` — on create and every change; phones get a plain `notify` frame (`phone.notify_proposal`; the phone protocol has no proposal frame, so Approve/Decline on android uses the REST endpoint). Outside the server (the jobs tick) `announce` POSTs `/api/proposal-event`. Daily review: `agents.daily_review` (false) + `daily_review_time` ("09:00") -> one internal job `kind=review` (`jobs.INTERNAL_KINDS`: `add/edit/cancel` refuse it unless `_internal=True`, so `schedule_job`/`manage_job` cannot create, edit or cancel-all it), reconciled by `ensure_daily_review()` at server start and after an `agents` settings patch. `run_daily_review` = Orchestrator profile with `tools=REVIEW_TOOLS` (read-only status tools + `propose`), no confirmer, source `schedule:<id>`; `dispatch(allowed=)` refuses everything else. A server restart marks `running` rows `failed` (`fail_orphans`). A turn whose text starts with `APPROVED_PREFIX` ("Owner approved proposal #") cannot call `decide_proposal` (no new owner words in it); an approval made while a session is busy starts when that turn ends (`_pickup_approved` in `run_turn`'s finally). **`decide_proposal` approve = `safety.enforce` at CRITICAL** (card "Approve proposal #id: title — agent: task", target `proposal:<id>`; auto mode never answers CRITICAL, no confirmer/unattended/decline policy denies, denial leaves it pending); decline needs no card; the REST button is the owner's own act and stays unconfirmed. Tests no longer read the real `~/.config/kravein` (autouse `_isolated_config_dir` in `tests/conftest.py`: CONFIG_DIR + settings cache) — the owner's `agents.orchestrator: true` used to hang web-transport tests. Pinned by `tests/engine/test_proposals.py`.
- Background tasks (#158, `agents/tasks.py`): `delegate(agent, task, context, wait=False)` queues a task and returns `task t3a9: system-ops started — …` at once; `wait=True`, no principal on the agent, or no host (CLI, jobs tick, tests: `tasks.configure` is called only by `kravein serve`'s lifespan) = the old blocking path. Both paths run `delegate.run_child(name, task, context, Parent, did)`; `Parent` is a *snapshot* (source, thread, principal, turn_no, stop, emit, confirm, memory) because a task outlives the parent's turn, thread and thread-local confirmer. `TaskManager`: table `tasks` in `agents.db`, `agents.max_parallel_tasks` 3 running, one running per sub-agent, FIFO queue (`_pump_locked`), `agents.max_queued_tasks` 10 open per principal, `agents.task_timeout_seconds` 900, each task on a daemon thread. **Safety:** the task's confirmer = `Host.confirm` -> the principal's newest *attached* session's `Session.confirm(..., turn_id="task:<id>")` (matches no message, so the global overlay; `deny_pending(turn_id)` releases just that card; Stop uses `deny_pending(keep_tasks=True)`); none attached, timeout, drop or an exception = deny. It carries `attended()` and `safety.enforce` will not auto-approve when it is false. A principal with nobody attached at start, or an unattended parent, gets no confirmer (unattended path, `needs-approval`). Denial memory: per task, seeded with a copy of the parent's declined targets in that turn; nothing flows back. Reports are untrusted: announced by one follow-up turn (several share one) run with `Agent.ask(allowed={"task_status"})` (narrowing only, intersected with the profile), a turn whose text starts `[task ` cannot `decide_proposal`; no attached session -> the report is appended to the thread (`history.append`, marked `[task id report] …`) and `Agent._refresh` reloads the thread when the store stamp changed. Claim is one `UPDATE announced=0->1`. `task_status`/`cancel_task` (Orchestrator only) read the manager's memory, no model call, <= 400 chars, principal-scoped. Stop (`cancelled` frame) cancels the current turn's tasks (`turn_no`) and lists others in `other_tasks`. Start-up `fail_orphans()` and shutdown mark active tasks `failed: server stopped`. Web contract: `GET /api/tasks?status=&id=`, `POST /api/tasks/{id}/cancel`, `{t:"task"}` frames (create, each tool step, end; not replayed). `Session.confirm(turn_id=)`, `deny_pending(turn_id=, keep_tasks=)` are new. Pinned by `tests/engine/test_tasks.py`.
- Live voice as the Orchestrator (#157, `live.py`): `LiveSession(agent=)` where `agent = agent.make_voice_agent(observer, thread_id)` (None when `agents.orchestrator` is off or the profile is broken -> the old all-tools session, byte-for-byte; the server passes `agent=` only when set). Per Live turn: `TurnMemory` reset at `turn_complete`, escalation (`agents.escalate_after_rounds`) narrows dispatch to `delegate`, a refused retry of a declined target refuses every further call that turn. Memory: each spoken turn is `history.append`ed (user = English transcript or typed text, assistant = said text + `[voice actions: name(target) outcome; …]`, names/outcomes/<=30-char targets only); the text Agent reloads via `_refresh`/`_keep_foreign_notes` (messages carry an `xid`). Reports unspoken at session end are saved as thread notes. `LiveSession.send_text(text)` drives a session by text (tests, live checks; `/tmp` scripts in the PR). HUD: `LLM.effective()`/`model_of()`; `_hello_payload`/`_state_snapshot` report the head of the failover chain + its own model, plus `voice_model`; `voice_state started` carries `model`, `orchestrator`.
