# skills

## Code map
- `kravein/skills/*.py` one module per category (windows, files, browser, interact, settings, media, notify, schedule, routines, …) · `kravein/platform/` desktop (Hyprland/Sway/X11), inputs (ydotool), audio, browser (Playwright), shell (only subprocess spawner) · `gentle.py`
- `kravein/skills/phone.py` — category `phone`: `list_phones`, `phone_status` (SAFE), `phone_flashlight`, `phone_set_volume` (MODERATE), `phone_open_url`, `phone_launch_app` (DESTRUCTIVE, confirmed). Drives the engine's `kravein/phone.py` (`call`, `connected`, `PhoneError`s); never touches the socket.

- Window ids/cwd (#82): `list_windows(as_json=True)` returns `[{id,title,app,pid,workspace,focused,cwd}]`; the text form shows `(id …, cwd …)`. `focus_window`/`close_window` take `id=` (exact backend handle: Hyprland address / sway con_id / X11 id); a stale id is refused, never name-matched. Web should use `desktop.window_record(w)` (`platform/desktop.py`) for `/api/windows`. `cwd` comes from `/proc` via `terminal_cwd` (null for non-terminals and for server-mode terminals sharing one pid).

- App name matching (#181), `platform/apps.py`: `_norm` drops case/space/-/_/. so "Anti Gravity" == "antigravity"; `_score` tiers exact normalised name > desktop id > prefix > substring > keyword > generic name > fuzzy (difflib >= 0.8); trailing filler words (ide/app/…) only as fallback. `resolve(query)` is the single ambiguity decision for `open_app` with and without workspace: exact name wins, else several matches -> refuse and list; kinds ("terminal", "browser") may take the top hit. Not found -> `not_found_message` lists the 3 closest installed names. Tests: `tests/skills/test_app_matching.py`.
- Apps on a workspace (#93): `open_app(app_name, workspace="")`; with a workspace it starts a **new** instance there via `backend.spawn_on_workspace` (Hyprland `exec_cmd(cmd, {workspace="N silent"})` / legacy `exec [workspace N silent] …`, verified live on 0.56.2; sway/X11 refuse with "not supported on this desktop"). Workspace must be a positive number or an existing workspace name; ambiguous app names list candidates; the result reports where the new window actually landed (forking launchers like browsers may ignore the rule). Structured list for the web panel: `kravein.platform.apps.list_entries(category="", limit=0)` -> `[{name, id, icon, exec}]` (visible entries, sorted by name); `list_apps` text unchanged.

- niri (#123): `desktop.NiriBackend` over `niri msg --json` (ids = niri window id; workspace label = name or `idx`, `idx@output` on non-focused outputs, not targetable by number). Actions take `--id`/`--window-id`, so no focus-first dance, but every change is re-read before returning True (niri clamps bad workspace indexes and still says Handled). `geometry` is None (IPC has no rect for tiled windows) so gentle scroll refuses; no kill (falls back to close); `move_cursor` unsupported. `open_app(..., workspace)`: no launch rule on niri, so `spawn_on_workspace` spawns, finds the new window id, moves it `--focus false`, refocuses the previous window (brief flash on the current workspace). `detect.find_niri_socket()` finds `/run/user/UID/niri.*.sock` (skips dead pids) and `_adopt_niri_session()` exports `NIRI_SOCKET`/`WAYLAND_DISPLAY`/`XDG_RUNTIME_DIR` so ssh/service runs work; session is then `wayland`. Screenshots fall back to `niri msg action screenshot-screen|screenshot-window --path` when grim is missing; region/named output refuse naming grim+slurp. Fixtures: `tests/skills/fixtures/niri/` (recorded from 26.04). Live-verified 2026-11-02 on niri 26.04 (laptop): workspaces come back in id order (2,3,1), so they are sorted by output/idx; `close-window`, `fullscreen-window`, `toggle-window-floating --id`, `move-window-to-workspace --window-id/--focus`, `focus-window --id` take ids, while `focus-workspace`/`spawn` take idx|name / argv; dynamic workspaces keep an empty one last. `inputs.status()` says when wtype is the fallback because `ydotoold` is down (never enabled by us). Installed on the remote now: ydotool (daemon inactive), wtype, wl-clipboard, grim. **#179 workspaces:** "workspace N" is always niri's per-output `idx` (real laptop: ids 1/7/8 = idx 1/2/3; ids never shown or accepted). niri workspaces are vertical: `switch_workspace('next'|'down'|'previous'|'up')` -> `focus-workspace-down/up` (`step_workspace`, verified by re-reading the focused idx; never column actions). `switch_workspace` reports the real current workspace on failure. `open_app(app, workspace=N, focus=True)` now switches the user there and focuses the new window, verified (`focus=False` = background launch).

- Merged skills + aliases (#140, 169→123 tools): `skills/_merge.py` (`run`, `unknown`) lets one skill take an `action` and dispatch to the plain functions that used to be skills (filemanager, browser tabs, memory, notifications/reminders, llm_admin, settings, …). The plain functions keep their own `safety.enforce()` and targets; the dispatcher only picks one. Old tool names stay registered as **aliases with a preset `action`** (see `registry`), so profile `tools:` lists and old audit names still resolve. Alias presets also bound what a profile can reach, which is why `recall` is its own SAFE skill (#142) — the merged `memory` tool would have let a read-only agent write.
- `skills/files.py`: `edit_file` (exact-string replace, refuses non-unique matches) and `search_text` (#136). Path checks go through `safety.check_path`, which now classifies sensitive paths: Kravein config/state/data are blocked; ssh/gpg/shell rc/systemd user units/autostart ask for confirmation. Skills pass the path to `check_path` and `enforce()` themselves.
- Agent profiles (`kravein/agents/<name>/SKILL.md`: front matter `name`, `purpose`, `tools`, `report_max_chars`, optional `model`; body = system prompt). Skills authored `orchestrator`, `system-ops`, `research`, `reviewer` (#142); `_example` is a test fixture. Loader/delegate/history live in the engine (`kravein/agents/*.py`), not here. A profile's `tools` names must exist in the registry (alias names count) — renaming a skill breaks profiles, so grep `kravein/agents/*/SKILL.md` first.
- Memory (`skills/memory.py`) reads/writes only `config.MEMORY_FILE`; the old in-repo `memory/long_term.json` fallback was removed (Windows leftover, #164).

- Preferred apps, resolver, verification, learned registry (#200). `apps.preferred_entry(kind)`: "terminal"/"browser"/"editor" (and synonyms, `_KINDS`) mean the setting `apps.preferred.<kind>` (no default in `config.py`), else detection: terminals kitty-first by *name*, NoDisplay helpers excluded (live bug: "kitty URL Launcher" won on the niri laptop), browser/editor via `xdg-settings`/`xdg-mime`. `platform/commands.py`: `resolve_command(name)` = registry -> exact normalised executable name (PATH, ~/.local/bin, ~/bin, /opt/*/bin) -> exact desktop-entry name -> its Exec program; "app"-style filler words are dropped, but "cli"/"command" never resolve (the GUI binary `antigravity` is not the CLI `agy`): candidates only. `check_command_line` checks every pipeline segment's program before `run_command`/`type_into_terminal`/`open_terminal` (builtins, assignments, sudo/env prefixes skipped; an exact off-PATH hit in the first segment is rewritten to its absolute path; shell aliases are not found and are refused). Evidence helpers: `process_snapshot`/`wait_for_process` (a NEW descendant of the window pid whose comm/argv matches; silence = "NOT confirmed", never "done"), `process_running`. Launch: `apps._launch_verified` looks for a new window or process (`_VERIFY_TIMEOUT` 5 s) and only then learns. `platform/appreg.py` -> `~/.local/share/kravein/apps.json` (`config.DATA_DIR`), normalised key -> `{kind desktop|cli, id, name, last_used, uses}`, flock + atomic replace, 400-key LRU cap, stale entries dropped on lookup, audit events `apps.registry_learn|hit|stale|forget`; model never sees it. Skills `resolve_command` (SAFE) and `forget_app` (MODERATE). `tests/skills/conftest.py` points `DATA_DIR` at a tmp dir (tests used to write the real registry) and re-exports `tests/conftest.py` names.

## Gotchas
- Docstring = tool schema. `describe_targets` + `:implicit` markers. See `CLAUDE.md` for the Hyprland, ydotool and browser findings.
- Phone skills resolve the phone *before* `enforce()` (so the confirmation names it) and pass its `device_id` to `call()`. Targets: `phone:<id>`, `phone:<id>:<command>`, `phone:implicit` when unnamed. Args and capability are checked before asking.
- A phone timeout/disconnect after sending means "outcome unknown" — never report success; success text comes only from the phone's returned data.
- Desktop `set_volume`/`open_url` and the phone tools name each other in their docstrings; keep it that way.
